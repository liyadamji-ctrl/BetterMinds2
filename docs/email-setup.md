# Signup emails: custom sender (Resend) so they stop landing in spam

Supabase's built-in sender is shared by thousands of projects and is rate
limited, so confirmation emails often go to spam. Fix: send from your own
verified domain through Resend. Do this in the **Supabase project
`otnbqtqlkpshlxppncmo`** (the one the live app uses).

## 1. Pick a domain

Use a domain you own (for example `prepped.ai` if that is yours). Sending from
a subdomain such as `mail.prepped.ai` keeps your main domain's reputation
separate. Below, replace `yourdomain.com` with the real one.

## 2. Resend: add and verify the domain

1. Create a Resend account, then **Domains -> Add Domain** (`mail.yourdomain.com`).
2. Resend shows DNS records. Add them at wherever the domain's DNS lives
   (Namecheap, GoDaddy, Cloudflare, Vercel Domains...). Copy the exact values
   from Resend; they look like this:

| Type | Name | Purpose |
|------|------|---------|
| MX | `send.mail` | bounce handling (SPF alignment) |
| TXT | `send.mail` | **SPF**: `v=spf1 include:amazonses.com ~all` |
| TXT | `resend._domainkey.mail` | **DKIM**: long value Resend gives you |

3. Click **Verify** in Resend. It can take a few minutes up to a few hours.
4. Add **DMARC** (not generated by Resend). One TXT record:
   - Name: `_dmarc.mail` (or `_dmarc` for the root domain)
   - Value: `v=DMARC1; p=none; rua=mailto:you@yourdomain.com`
   Start with `p=none` (monitor only). After a few weeks of clean reports you
   can move to `p=quarantine`.
5. **API Keys -> Create API Key** (sending access). Copy it once.

## 3. Supabase: switch on custom SMTP

**Authentication -> Emails -> SMTP Settings -> Enable custom SMTP**

| Field | Value |
|-------|-------|
| Sender email | `noreply@mail.yourdomain.com` |
| Sender name | `Prepped` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | the Resend API key |

Save. (Optional: raise **Authentication -> Rate Limits -> emails per hour**; the
default is low.)

## 4. Supabase: cleaner confirmation email

**Authentication -> Emails -> Templates -> Confirm signup**

Subject: `Confirm your Prepped account`

Body (paste as HTML):

```html
<div style="font-family:Arial,Helvetica,sans-serif;max-width:480px;margin:0 auto;padding:24px;color:#1f2933">
  <h2 style="margin:0 0 12px;color:#2f4156">Welcome to Prepped</h2>
  <p style="line-height:1.5">Thanks for signing up. Confirm your email address to finish setting up your account.</p>
  <p style="margin:24px 0">
    <a href="{{ .ConfirmationURL }}"
       style="background:#2f4156;color:#ffffff;padding:12px 20px;border-radius:8px;text-decoration:none;font-weight:bold;display:inline-block">
      Confirm my email
    </a>
  </p>
  <p style="font-size:13px;color:#667085;line-height:1.5">
    If the button doesn't work, copy this link into your browser:<br>
    <span style="word-break:break-all">{{ .ConfirmationURL }}</span>
  </p>
  <p style="font-size:13px;color:#667085">If you didn't create a Prepped account, you can ignore this email.</p>
</div>
```

Keep the text plain and the link count low: lots of images, link shorteners or
all-caps subjects push mail toward spam.

## 5. Test

Sign up with a fresh Gmail and an Outlook address. Check the inbox, then in
Gmail use **Show original** and confirm `SPF: PASS`, `DKIM: PASS`,
`DMARC: PASS`.
